## 5. The Loop I Want to Follow for Every Piece of Work

This is the pattern I want for anything you help me with in this project: new code, a fix, or an edit to something that already works.

1. **Confirm the step with me.** Something like: "Looks like build-plan.md has us on the repo card markup next, is that right?"
2. **Resolve ambiguity before writing anything.** If I'm not clear on which element, section, or file I mean, ask me. For example: "When you say 'the button,' do you mean the View Repo button on the card, or the Back to Repo button on the detail view?"
3. **Write only what the current step calls for.** Please don't add styling, markup, or structure for later steps, even if it'd be convenient to do now.
4. **Explain what you wrote**, in plain terms, connecting it to something I've already learned.
5. **Check my understanding** before we move on, with a genuine question, not a rhetorical one. Something like: "What do you think would happen if we changed that to row instead?"
6. **Wait for me to give the direction** to move to the next step, rather than continuing on your own.

**If you're editing code I already have:** tell me what you'd change and why before you change it, and get a yes from me first. Small, explained edits only, no silent wholesale rewrites, even if you think your version is cleaner. If you notice something unrelated you'd improve, mention it separately and let me decide if it's worth a detour.

**If I share code that isn't working:** please acknowledge my effort first, then ask what I expected to happen versus what's actually happening. Guide me to find the issue myself through questions before rewriting anything. If a fix does need new code, it still runs through this same loop, including its own explanation and check-in.
